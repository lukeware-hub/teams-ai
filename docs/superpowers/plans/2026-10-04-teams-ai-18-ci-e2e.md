# Plan 18: CI and automated e2e

## Goal
Every PR and push to main runs typecheck and tests, and one automated e2e drives the CLI entry against a temp git remote.

## Approach
1. CI: `.github/workflows/ci.yml` already exists (pull_request and push to main, Node 22.13, npm cache, `npm ci`, typecheck, `npm test`, web install/test/build, no secrets). It meets the requirement; left unchanged.
2. E2E: `test/e2e/pipeline.e2e.test.ts` using `test/fixtures/git-remote.ts` (real bare origin and clone, git only).
   - Full pipeline: `main(['run', ...])` with the Run injected through the CLI factory seam; Docker gates, GitHub and the agent steps are faked (FakeExec, FakeGh, scripted steps). Asserts exit 0, `finished: complete`, both tasks `merged`, a `RunFinished` journal event, and the merged files on origin/main.
   - Dry-run entry: `run --dry-run --draft` with an empty PATH and throwaway HOME. Asserts exit 2 with `preconditions failed` / `claude is not logged in`.

## Gap (documented, not faked)
- `run --dry-run` cannot go further without claude, gh and Docker on the host: `preconditions()` in `server/cli.ts` requires them, and the dry-run Scenario has no steps preloaded ("set steps in code"). So the CLI dry-run test asserts only the furthest honest milestone (project and spec loaded, preconditions reached). The full-pipeline test does not use fake-claude; it fakes at the `runStep` seam like `test/orchestrator/run.test.ts`.
- The `test/fixtures/todo-api` fixture does not exist in the repo; the e2e builds its remote from `test/fixtures/contracts.ts` instead.
- Follow-up: a dry-run that skips host preconditions and preloads a Scenario would let the real `run --dry-run` reach `complete`.

## Verification
`npx tsc --noEmit`, `npx vitest run test/e2e` (about 10 s), full `npx vitest run`.

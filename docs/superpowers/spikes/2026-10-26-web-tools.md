# Spike: web tools in a refinement step (2026-10-26)

Question: can the Spec Kit answer step research on the internet, and can the agent reach addresses that only the owner's machine should reach?

## Setup

- One real call per configuration, run inside the production container with the production runner, so the sandbox and the permission settings are the ones a refinement step gets.
- Agent: role PO, with the tools Read, WebFetch, WebSearch and Bash. Network allowed domains: none, as in refinement.
- Configuration A grants `WebFetch` and `WebSearch` without any limit. Configuration B grants `WebFetch(domain:example.com)` and `WebSearch`.
- Cost: about 8 cents per configuration.

## Results

| Check | A: WebFetch, no limit | B: WebFetch for example.com only |
| --- | --- | --- |
| Fetch `https://example.com/` | Fetched | Fetched |
| Fetch `http://127.0.0.1:8787/` (the app itself) | Reached the app; an encrypted-handshake error, not "connection refused" | Denied by permission |
| Fetch `http://dind:2375/version` (a name without a dot) | Refused by the tool | Denied by permission |
| WebSearch for a public question | Returned results with links | Returned results with links |
| Bash `curl` to `https://example.com` | Blocked by the sandbox (network denied) | Allowed, status 200 |

## Findings

1. WebFetch does not obey the sandbox network list. With no domains allowed, it still fetched `example.com`.
2. A name without a dot is refused, but an address written as numbers is not. `127.0.0.1` reached the app. The tool does not refuse private addresses.
3. A domain rule for WebFetch also opens the Bash network to that domain. Configuration B let `curl` reach `example.com`.
4. Bash ran in both configurations although the role's allow list has no Bash rule. The sandbox lets Bash commands run and limits them by file and network rules. This needs a security review.
5. WebSearch returned results with links. The container did not connect to the result pages in these calls.
6. Both calls ended with an output-format error, because the spike's answer format was not the real card format. The tool results are what this spike measured.

## Decision

The spike's pass rule says that a private address must be refused. Under configuration A it was reached, so the spike fails that rule. Internet research through WebFetch is not shipped. The answer step stays on the six documents.

Options for the owner:

- A. Research with WebSearch only. The container fetches no page; the agent works from search results and links, and the owner confirms every suggestion. Needs a check that WebSearch makes no connection from the container.
- B. WebFetch behind a check that refuses numeric addresses and private names, plus a spike that proves a redirect to a private address is refused. The check cannot see redirects by itself, so the spike is required.
- C. No internet research for now.

Recommendation: A, then B only after its own spike.
